# Agent 工作流

本文件承接 `AGENTS.md` 的启动、派发、工作树、状态和交接细则；它不定义授权默认值，所有外部
动作仍以 [`review.md`](review.md) 为唯一正文。

## 启动与领单

1. 先检查 `~/.codex/automations/nl2sql-dispatch/automation.toml`。缺失时使用当前调度上下文提供的
   `frontline-heartbeat.md` 重建；仓库不固化本机用户名、派发绝对路径或会话 ID。
2. 检查调度上下文给出的派发目录。本战线任务存在时，在不突破本轮授权和安全边界的前提下执行；
   无任务时不创建业务改动。
3. 依次读取 `PROJECT.md`、`docs/status.md` 和当前 `docs/work/` 合同，再核对 Git、代码、测试与
   易漂移的外部事实。文档与现场冲突时，以实测为准并落盘纠正。
4. 实质工作前固定“做什么 / 不做什么 / 怎样算完成”。跨文件、契约变化或不可逆动作使用完整
   Goal、Non-goals、WHEN-THEN 验收标准、回滚和规则复述。

## 派发与战报

- 派发单只授权其明确范围。里程碑完成、连续失败阻断或边界拿不准时，在调度上下文指定的战报
  顶部追加带时间戳的三行：成了什么 / 下一步 / 要不要用户动。
- 完成派发后，先验证源和归档目标都在授权目录内且目标不存在，再移动；随后验证源消失、归档
  存在且哈希不变、三行战报正确，以及接手前 Git 改动未受影响。
- 派发未指定回执位置时写 `docs/status.md`；项目历史证据只追加到当月日志，不回写旧条目。

## 工作树与交接

- 同一可写 worktree 同时只有一个写入者。发现用户或其他任务改动时不得清理、覆盖或混入；需要
  隔离时从已验证基线创建独立 worktree 和任务分支。
- 当前事实、队列、阻碍和下一检查点写入 `docs/status.md`；详细证据进入月度日志和对应切片合同。
  会话记忆、进程状态或本机临时路径不能成为项目事实源。
- 交接必须给出精确分支 / head、工作树状态、已运行证据、外部动作状态、剩余阻碍和下一条命令。
