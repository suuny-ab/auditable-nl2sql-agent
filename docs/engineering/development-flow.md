# 开发与完成合同

本文件承接切片定义、实现边界、复用顺序、错误处理和验证细则。稳定产品范围仍以
[`PROJECT.md`](../../PROJECT.md) 为准，当前事实以 [`docs/status.md`](../status.md) 为准。

## 一个切片

- 一个任务只交付一个可验收闭环；新想法先进入候选队列，不顺手实现。
- 每个切片至少写清 Goal、Non-goals、可执行验收标准和回滚；复杂任务还要在正文复述当场最相关
  的 2–3 条规则。
- 范围变化必须先取得用户确认；授权处理见 [`review.md`](review.md)。

## 实现与复用

- 生产依赖保持 `API → workflow → tools/data`；`evals` 可以调用产品代码，产品代码不得导入
  `evals`。
- 工具总数不超过 5：schema 读取、只读 SQL 执行、结果校验、证据绑定、审批门。
- SQL 安全同时依赖只读连接、`query_only` / authorizer 等机械边界；提示词、字符串黑名单和人工
  批准都不能把产品变成写库产品。
- 优先复用本仓模式、Traceable 已验证结构、标准库、维护良好的依赖和厂商正式接口；新增薄适配
  层时记录不能直接复用的原因。

## 错误与验证

- 遇错先复现、读完整报错并检查最近改动；同类操作连续失败 3 次立即停止并报告，不做猜测式
  连续修复。
- 先运行最便宜的相关测试，再按风险补集成或容器验证。测试至少覆盖成功路径和对应失败关闭；
  安全测试同时证明动作被拒绝且状态未修改。
- 机器能稳定判断的合同写入测试或检查脚本；文档链接结果，不复制另一套会漂移的机器事实。
- 文档当前态防腐门运行 `python tools/doc_gardener.py --scope current --fail-on stale`；手动全扫用
  `python tools/doc_gardener.py --scope all --format markdown`。园丁只报告不改写，`review` 项须人工
  对照 `PROJECT.md` 与 `docs/status.md` 裁决。
- 完成前运行相关测试、`compileall`、依赖检查和 `git diff --check`；确认未跟踪密钥、运行数据库、
  构建产物、模型权重或私有评测材料。

## 完成与回执

- 没有真实输出不得宣布完成。回执必须说明证据证明什么、不证明什么，以及 Provider、费用、凭据、
  真实数据和外部写入是否发生。
- 当前状态保持短小；旧证据只追加到 `docs/status-log/YYYY-MM.md`。本地提交边界清楚，不混入
  无关改动；远端动作按 `review.md` 执行。
