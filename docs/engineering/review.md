# 授权与机器检查

本文件是仓库内授权默认值和 Git 外部动作的唯一事实源。它记录用户已批准的项目流程，但文件本身
不能为某个候选授予权限；具体派发单和当前用户指令必须继续满足下列档位。

## 机器检查

- 可稳定判断的事实应进入测试或检查脚本，并在漂移时失败关闭；绿色只证明实际登记并执行的断言。
- 文档新增机器可判定的主张时，同一变更应增加独立事实源上的断言；关键词存在不能替代行为证明。
- 本项目治理检查固定验证 `AGENTS.md` 行数、规则指针存在，以及授权正文只有本文件一个所有者。

## 授权默认值：唯一正文

- **默认通过**：范围内、可逆且无新增外部影响的本地编辑、测试、文档 / 状态更新和本地提交；
  当前候选远端 CI 全绿后的本仓 squash 合并也按项目常设档执行。每个动作仍须留可核验回执。
- **授权请求**：推送新分支、创建 Draft PR，以及账户预算帽内的新 Provider 调用。把有界请求写入
  Git 外的 `派发/授权请求.md` 后继续无依赖本地工作；只有中心或用户明确批准后才能执行。
- **红灯**：公开发布、部署、新费用渠道、安全 / 隐私 / 凭据边界变化、新增或改变公开主张，以及
  破坏性操作，必须取得用户当次明确确认；目标、影响或调用上限不清时立即停手。

授权必须绑定具体候选或精确 head、具体动作与外部影响。任务、Git 文件或历史授权不能替代当前
裁决；新 head、新 Provider 轮次或新增动作重新走相应档位。所有获准 Provider
调用自动重试为 `0`，代码层不实现账户预算。

## Git 与外部动作

- 接手前确认基线、未提交改动和唯一写入者；本地提交不得混入无关修改。
- 禁止强推或删除 `main`。推送后核对远端 head；Draft PR 绑定精确 head，合并前核对要求的 CI、
  可合并状态和授权仍有效。
- squash 合并后记录 merge SHA，并按风险检查 main CI 与运行时事实；CI 绿色不自动证明发布或部署。
- 破坏性清理优先使用可恢复方式，并在动作前验证精确目标不越出任务目录。
