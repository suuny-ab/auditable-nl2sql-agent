## 做什么

- 从真实的确定性完成 run 提取问题、SQL、schema 快照、结果和校验结论，组成候选 evidence。
- 两个独立 Python 进程以不同字典插入顺序计算规范 JSON 和 SHA-256。
- 分别修改 SQL、schema 与结果，验证任一受绑定字段变化都会改变指纹。
- 验证截断结果、行宽不匹配、`NaN` 和二进制值失败关闭。
- 比较探针各阶段的合成业务库 SHA-256。

## 不做什么

- 不修改正式 workflow、数据库执行器、依赖或 CI。
- 不实现正式 evidence 节点、自然语言回答、语义正确性判断或数字签名。
- 不提交探针脚本、SQLite、JSON 运行产物或虚拟环境。
- 不推送 GitHub。

## 怎样算完成

- 两个独立进程对等价 evidence 得到完全相同的规范 JSON 字节长度和 SHA-256。
- 修改 SQL、schema 或结果后得到三个不同于基准的 SHA-256。
- 四类非法输入均被明确拒绝，且没有生成可接受指纹。
- 所有阶段前后业务库 SHA-256 相同。
- Git 只出现本合同和完成后的状态记录，不出现正式产品代码或运行产物。

## 声明边界

指纹只证明候选 evidence 的字段被稳定绑定，并提供意外变化检测；它不是数字签名，也不证明
SQL 的业务语义或答案正确。
