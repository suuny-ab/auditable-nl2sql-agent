# FROZEN-EVAL-30-027 切片合同

## Goal

在原有 20 条冻结合成评测案例完全保留的前提下，新增 10 条零重复、难度不低于原集的未见案例，
形成 30 条新冻结集；随后只运行一轮完整真实 Provider 评测，保存扩充后第一份独立基线。

## Non-goals

- 不修改业务知识层、训练对、确定性意图门、生成逻辑、Provider transport 或工作流。
- 不修改原 20 条问题与 gold，不根据评测结果改题、调参、补跑失败案例或重复刷分。
- 不增加业务表、真实数据、依赖、代码层预算、API、网页、容器或部署能力。
- 不把扩充后的单次合成集结果外推为生产可靠性或真实业务泛化能力。

## Acceptance criteria

1. **WHEN** 加载扩充后的数据集，**THEN** 严格合同恰好得到 30 条、30 个唯一 ID 与 30 个唯一问题，
   原 20 条内容不变，新 10 条 ID 固定且与原题零重复。
2. **WHEN** 统计类别，**THEN** 成功 / 歧义 / 无答案 / 越权 / 注入为 `12/5/5/4/4`；这是将
   `8/3/3/3/3` 按 1.5 倍扩充后的最大余数离散分配，两个额外余数给语义歧义与数据缺失。
3. **WHEN** 校验新题标注，**THEN** 4 条成功题具有可复算参考 SQL 与固定结果，2 条歧义、2 条
   无答案、1 条越权和 1 条注入只保存预期路由；新越权与无答案题不得预写 SQL。
4. **WHEN** 复算全部有参考 SQL 的案例，**THEN** 成功结果逐字段相等，越权参考案例执行尝试为
   `0`，业务 SQLite 前后 SHA-256 不变。
5. **WHEN** 完成本地实现，**THEN** Python 全量、编译、依赖、文档园丁、治理、Web、Compose 配置、
   严格 JSON 与差异检查全部通过。
6. **WHEN** 开始真实评测，**THEN** checkpoint 与报告路径都预先不存在；30 个案例只各运行一次，
   自动重试为 `0`，不补跑，真实 Provider usage 回执不超过 30 条。
7. **WHEN** 评测结束，**THEN** 保存正确率、成功案例执行率、人工介入率、usage、错误案例、越权
   执行数、逐案例与整轮业务库哈希，并把它记为扩充后基线，不倒写原 `20/20` 结果。
8. **WHEN** 本地证据完整，**THEN** 按本单预授权推送精确 head、创建 Draft PR；web / api /
   container 三个 CI job 全绿且可合并后按常设档 squash 合并，并复核 main CI。

## Rollback

回滚本切片提交即可恢复原 20 条评测合同与文档；运行报告、checkpoint 和业务数据库只存在于 Git
忽略目录，可单独移除且不影响产品或历史基线。
