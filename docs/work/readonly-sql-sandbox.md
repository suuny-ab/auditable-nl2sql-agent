# READONLY-SQL-001：合成数据与只读 SQL 沙箱

> 状态：`completed`
>
> 立项来源：用户于 2026-07-31 批准的项目立项书。

## 开工三问

- **做什么**：创建 4 表合成电商 SQLite 数据库，实现结构化 schema 读取和受机械边界约束的
  SQL 查询，并给出可重复测试。
- **不做什么**：不生成自然语言 SQL，不接 LangGraph/Provider/API，不实现 trajectory、结果
  校验、证据绑定或人工审批语义，不接真实数据。
- **怎样算完成**：以下验收项全部有本地测试输出，且项目状态文件回写真实结果。

## 验收合同

1. 初始化器创建 `customers`、`products`、`orders`、`order_items` 四张表和确定性合成记录。
2. schema 工具返回字段、主键和外键关系，不暴露 SQLite 内部表。
3. 聚合查询排除取消订单后的销售额固定为 `5946.0`，可重复得到相同结果。
4. `INSERT`、`UPDATE`、`DELETE`、DDL、`ATTACH` 和 `PRAGMA` 查询均被拒绝。
5. 失败操作后记录数不变；单次返回行数不能超过调用方给定的正整数上限。
6. CI 使用只读仓库权限运行编译检查和相同测试。

## 复用决定

| 资产 | 决定 | 原因 |
| --- | --- | --- |
| Traceable `api/src`、`api/tests` 布局 | 复用 | 已验证、边界清晰，适合 Python 产品代码 |
| Traceable SQLite run store | 不复制代码 | 它是可写运行状态库，没有模型 SQL 的只读/授权边界 |
| Traceable 完整 CI proof 工具链 | 暂缓 | 空仓首切片只需标准库编译与单测，完整链会扩大治理面 |
| Python `sqlite3` | 复用 | 标准库已提供 URI 只读连接、authorizer 和进度中断 |
| SQL 字符串黑名单 | 拒绝 | 注释、CTE 和方言变化容易绕过，不能作为机械安全边界 |

## 可证伪点

- 任一写操作成功、数据库记录变化或内部表泄露即失败。
- 只靠 SQL 首词判断、只在调用前加 `LIMIT` 或仅靠提示词约束均不满足本切片。
- 测试绿只证明 SQLite 本地事实层，不证明 NL2SQL 正确率、Agent 恢复、审批或完整可审计闭环。

## 完成证据

- 固定非取消订单销售额为 `5946.0`；越界语句拒绝后订单数与 schema 保持不变。
